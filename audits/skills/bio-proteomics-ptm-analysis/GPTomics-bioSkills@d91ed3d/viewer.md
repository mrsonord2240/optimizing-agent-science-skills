## Lead 4 - double filter vs treat-style testing (CONFIRMED in part)

SKILL.md line 170 uses `adj.pvalue < 0.05 & abs(log2FC) > 1`. The differential-abundance Skill (its lines 59, 89, 212-216) says never to use this post-hoc double filter and to use `treat()` instead, so the two Skills are inconsistent.

`runs/lead4_doublefilter_sim.R` (20 simulations of 2000 sites, 4 v 4, 30% true |log2FC| drawn from U(0.2, 2)):
```
                        FDP_vs_2fold_claim FDP_exact_nulls mean_calls
double_filter_ttest                  0.091           0.015     157.45
double_filter_moderated              0.129           0.035     237.80
treat_lfc1                           0.060           0.010       0.65
```

- For the claim "changed more than 2-fold", the double filter's false-discovery proportion is about 2-2.6x the nominal 5%.
- It is not >50% as in Ebrahimpoor & Goeman's setting.
- treat(lfc = 1) controls the error rate but has almost no power at n = 4.
- groupComparisonPTM has no threshold test, but ADJUSTED.Model provides log2FC, SE and DF, so a TREAT-style p-value can be computed directly (recommendation P2).
